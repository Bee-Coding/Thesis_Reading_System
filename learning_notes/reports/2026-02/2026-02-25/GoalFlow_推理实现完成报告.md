### 2. 问题分析与解决

**问题**：`selected_goal` 选择不准确

**分析过程**：
1. 检查可视化结果，发现目标点偏差大
2. 分析推理代码，发现评分公式问题
3. 对比训练和推理的计算方式
4. 发现数值尺度不匹配

**根本原因**：
- `pred_dis` 是 logits（未归一化）
- `pred_dac` 是概率（0-1）
- 直接相加导致 DAC 贡献为 0

**解决方案**：
- 使用对数空间评分
- 符合论文公式
- 与训练一致

### 3. 对数空间的数学原理

**为什么使用对数空间？**

1. **数值稳定性**
   - 概率值可能非常小
   - 对数避免下溢

2. **符合论文**
   - 论文公式：δ_final = w1*log(δ_dis) + w2*log(δ_dac)
   - 理论推导基于对数概率

3. **与训练一致**
   - 训练时使用 log_softmax
   - 推理时也应该使用对数空间

**数学推导**：
```
训练损失：
L_dis = -Σ true_dis * log_softmax(pred_dis)
L_dac = BCE(pred_dac, true_dac)
L_total = w1 * L_dis + w2 * L_dac

推理评分（应该对应）：
score = w1 * log_softmax(pred_dis) + w2 * log(pred_dac)
```

## 💡 关键洞察

### 1. 推理与训练的一致性

**重要原则**：推理时的计算应该与训练时的损失函数对应

- 训练时优化的是损失函数
- 推理时应该使用对应的评分函数
- 不一致会导致性能下降

### 2. 数值尺度的重要性

**教训**：不同数值范围的量不能直接相加

- logits 范围：±∞
- 概率范围：0-1
- 需要统一到同一空间（如对数空间）

### 3. 调试技巧

**有效方法**：
1. 可视化结果（直观发现问题）
2. 打印中间值（检查数值范围）
3. 对比理论和实现（找出不一致）
4. 创建测试脚本（验证修复）
